# 賽程顯示每場出賽選手 — 設計 spec

日期：2026-08-10
狀態：設計完成，待實作

## 目的

比賽計分頁的賽程每列目前只顯示「甲隊 vs 乙隊」，看不出這一場是誰上場。
試算表「總賽程表(含出賽選手)」早已排到選手粒度（每場每邊指名兩人），
系統接不住這一層，於是：

- 選手要知道自己第幾輪上場，只能回頭翻試算表
- 觀眾看計分板看不出場上是誰
- 隊長輸分時無從確認「這場是不是我隊的那一場」

同時處理一件相關的遺留工作：抽籤結果尚未掛進資料庫，
`tournament_teams.name` 現在還是 `A`~`E` 五個字母，畫面上顯示的是字母而非隊名。

## 範圍

**做**：

1. 掛上抽籤後的隊名與整隊名冊（`docs/tournament/賽前作業.md` 步驟 4）
2. 資料庫記錄每場雙方的出賽選手
3. 賽程列改版，顯示雙方隊名與各自的兩位選手
4. 輸分彈窗顯示本場我方選手

**不做**：

- 排名表不加「點開看隊員名冊」（無此需求；名冊是本名、賽程是暱稱，混在同一頁徒增困惑）
- 不做管理介面或當場改名單的功能。名單以試算表為準，改了重跑一次 SQL 同步
- 不做暱稱↔本名的對照表（見「名字的處理」一節）
- 不動排名計算、輸分狀態機、RLS 政策

## 前置事實

### 字母與隊名的對應（雙來源驗證）

試算表「等級校正與分組」分頁 J~N 欄的五份名冊，與 `seed-2026-08-20.sql`
「抽籤後」五段 update 的分隊 1~5 逐人吻合；
另以試算表「總賽程表(抽籤結果)」的對戰組合，比對 seed 中 30 場的字母組合，
前三輪九場全部一致。兩條獨立路徑得到同一組對應：

| 字母 | 隊名 | seed 分隊 | 人數 |
|---|---|---|---|
| A | 羽林萌主 | 分隊 4 | 5 |
| B | 綠鯉魚與驢 | 分隊 1 | 6 |
| C | 忠男的嘍囉們 | 分隊 3 | 6 |
| D | 拍謝阮冠軍 | 分隊 2 | 6 |
| E | 翰林小羽E | 分隊 5 | 5 |

`team_a` 對應試算表列的左側、`team_b` 對應右側，兩張分頁的欄位順序一致。

### 前端未使用 `tournament_teams.players`

`tournament_public_payload` 有輸出 `teams[].players`，但 `tournament.js`、
`standings.js`、`tournament-form.js`、`tournament.html` 均未讀取。
因此整隊名冊存本名不影響任何畫面。

## 名字的處理

賽程顯示一律用試算表出賽表的**暱稱**（小悠、雨彤、Eating、Rex、Anita…），
理由是球場上就是這樣互相稱呼，最好辨認，且資料可直接從試算表搬，無需轉換。

試算表不存在暱稱↔本名對照表。以反推名冊（見下節）與分組表逐隊比對後，
可用「本名去姓」規則加排除法推得完整對應
（例如 `Rex`=陳彥文、`Anita`=蔡依玲、`小悠`=吳玉婷、`小于`=洪于婷、`阿輊`=林丞輊）。
但這是推論而非試算表明載，顯示層也不需要本名，因此不建立、亦不依賴這份對應。

`tournament_teams.players`（整隊名冊）沿用 seed 現成的本名版本。
兩者不一致但不衝突——名冊不上畫面，賽程不引用名冊。

### 各隊暱稱名冊用反推取得

每場的左右隊伍已知，該場出賽選手必屬該隊，掃過 30 場即得每隊的暱稱集合。
不需要人工建對照表。反推同時作為資料校驗，見下節。

## 校驗

灌資料前對試算表資料跑以下檢查，**任一不通過就停下來回報，不自行修正、不逕自灌入**：

1. **一人一隊**：同一個暱稱不得出現在兩個不同隊伍的出賽名單中。
   出現即代表試算表有誤植。
2. **人數吻合**：反推出的每隊暱稱數，應等於上表的人數（5/6/6/6/5）。
   短少代表某人十輪都未排到上場——可能屬實，也可能是漏打，須人工確認。
3. **賽點一致**：出賽表與抽籤結果表同一格的賽點（男雙/女雙/混雙）須相同。
4. **對戰組合一致**：抽籤結果表 30 場的隊伍組合（含 A/B 左右方向），
   須與 seed 中 30 場的字母組合逐場吻合。

## 設計

### 1. Schema：`tournament_matches` 增兩欄

```sql
alter table tournament_matches
  add column if not exists players_a jsonb not null default '[]'::jsonb,
  add column if not exists players_b jsonb not null default '[]'::jsonb;
```

格式比照 `tournament_teams.players`：`[{"name":"小悠"},{"name":"雨彤"}]`。

`default '[]'` 是這次的安全底線——欄位加下去、資料還沒灌，
既有查詢與畫面完全不受影響。

### 2. 灌資料的 SQL 冪等可重跑

新檔 `docs/tournament/lineup-2026-08-20.sql`，以 `(round_no, court_no)` 為 key 做 update：

```sql
update tournament_matches m set
  players_a = v.pa::jsonb,
  players_b = v.pb::jsonb
from (values
  (1, 1, '[{"name":"小悠"},{"name":"雨彤"}]', '[{"name":"庭禎"},{"name":"杰妮"}]'),
  ...  -- 30 列
) as v(round_no, court_no, pa, pb)
where m.tournament_id = (select id from tournaments
                         where name = '第三屆翰林匹克羽球運動會'
                           and held_on = '2026-08-20')
  and m.round_no = v.round_no and m.court_no = v.court_no;
```

純 update、無 insert，重跑只是把同樣的值再寫一次。
這正是現有 `seed-2026-08-20.sql` 缺少而導致「不可重跑」的性質；
試算表日後有異動，改完重跑此檔即可同步。

檔末附一段核對查詢（純 `select`），列出 30 場的 round/court/雙方選手供肉眼比對。

### 3. 隊名與名冊

執行 `seed-2026-08-20.sql` 既有的五段「抽籤後」update，
把 `<字母>` 換成上表的對應字母，並將隊名一併改為正式隊名。
此步驟與出賽名單獨立，可先做。

### 4. RPC：`tournament_public_payload` 多吐兩個 key

在 matches 的 `jsonb_build_object` 中加入：

```sql
'playersA', m.players_a, 'playersB', m.players_b
```

僅此兩處，不動函式簽章、不動 `tournament_public_view` /
`tournament_captain_view` / `tournament_report_score`。

舊版前端收到多餘的 key 不會出錯，因此上線順序可拆為
**加欄位 → 灌資料 → 改 RPC → 改前端**，每一步皆可獨立驗證與回退。

### 5. 前端：賽程列改為左右對稱兩排

`renderSchedule` 的每列由單排改為兩排：

```
┌────────────────────────────────────────┐
│ [場地1 女雙]              21：15 已確認 │
│ ● 忠男的嘍囉們     vs   拍謝阮冠軍 ●   │
│   小悠・雨彤             庭禎・杰妮     │
└────────────────────────────────────────┘
```

- 上排：`event-chip` 靠左，比分與狀態標籤靠右
- 下排：兩隊各佔一半，隊名一行、選手一行；右側整體靠右對齊，
  隊伍色點分置最外緣（左隊在左、右隊在右），與現有色點語意一致
- 選手緊貼自己的隊名下方，「誰跟誰同隊」無歧義——這是選定此版面的主因

保留的現有行為，不得改動：

- `match-mine` 左緣紅條與底色
- `just-confirmed` 首次確認的閃爍（含 `seenConfirmed` 的記錄與清除邏輯）
- `can-report` 的可點擊與 `openReportForm` 綁定
- 一輪一張 `round-card`、輪次標題、依 `round_no` / `court_no` 排序

**空名單退回現況**：`playersA` / `playersB` 為 `[]` 時，該側只顯示隊名，
版面等同今日。SQL 未執行或執行失敗時，畫面不會空白或報錯。

### 6. 輸分彈窗補一行我方選手

`openReportForm` 在既有的「第 N 輪　賽點」「時段　場地」之下，
補一行「本場我方：宏彬・彥呈」。我方選手取
`myTeamId === teamAId ? playersA : playersB`。名單為空時整行不渲染。

### 7. 新純函式 `formatLineup`

置於 `js/tournament-form.js`（該檔已是計分頁的純函式集散地）：

```js
formatLineup([{name:'小悠'},{name:'雨彤'}])  // → '小悠・雨彤'
formatLineup([])                             // → ''
formatLineup(undefined)                      // → ''
```

以 `・`（U+30FB）分隔，與畫面一致。

## 錯誤處理

| 情況 | 行為 |
|---|---|
| `playersA` / `playersB` 缺漏或為 `[]` | 該側只顯示隊名，其餘照舊 |
| 欄位存在但非陣列（人為誤植） | `formatLineup` 回空字串，等同空名單 |
| RPC 尚未更新、前端已更新 | payload 無此 key → 視為空名單 → 顯示今日版面 |
| 名字過長導致換行 | 下排允許換行，不裁切；一列高度隨之增加 |

## 測試

**jest**：

- `formatLineup`：兩人、單人、三人以上、空陣列、`undefined`、非陣列
- `tournament-api.test.js` 補一例：payload 帶 `playersA` / `playersB` 時薄封裝原樣透傳

**瀏覽器**（照專案慣例，渲染層不寫自動化測試）：

- 觀眾模式：30 場皆顯示雙方選手，長隊名（忠男的嘍囉們）不破版
- 隊長模式：我隊場次紅條仍在；可輸分場次仍可點開；輸分彈窗顯示我方兩人
- 空名單：手動將一場的 `players_a` 設回 `'[]'`，確認該側退回只顯示隊名
- 手機寬度（375px）與桌機寬度各看一次

## 邊界清單

- 名單未灌（全部 `[]`）→ 全頁等同今日版面
- 僅單側有名單 → 有的那側顯示選手，另一側只有隊名
- 名字含空白或全形字元 → 原樣顯示，不做 trim 以外的處理
- 一輪三場中僅部分已確認 → 比分與狀態各自獨立，不受選手列影響
- 已確認場次的比分閃爍動畫 → 兩排版面下仍只在該列觸發

## 上線順序與回退

| 步驟 | 動作 | 回退方式 |
|---|---|---|
| 1 | 跑隊名與名冊 update | 重跑改回字母 |
| 2 | `alter table` 加兩欄 | 保留即可（無副作用） |
| 3 | 跑 `lineup-2026-08-20.sql` | 重跑改回 `'[]'` |
| 4 | 更新 `tournament_public_payload` | 貼回舊版函式定義 |
| 5 | 前端改版並部署 | `git revert` 後重新部署 |

前端部署務必同步 bump `sw.js` 的 `CACHE_NAME`，
否則手機上已快取的舊版需重整兩次才生效（見 CLAUDE.md「當天注意事項」）。
