# 應援條交界火花（短設計）

2026-11-17。接續 `2026-11-16-friendly-match-design.md` 的公司應援條。使用者看過三種樣式的試玩後選了 A「交界火花」。

## 為什麼

應援條純粹是炒氣氛。現在按下按鈕，只有按的人自己看得到按鈕縮一下；別人的應援要等 3 秒一次的輪詢才會讓數字跳動。
火花要讓場邊每個人都**看得到對方公司正在加油**：兩色交界就是兩家公司互相拉鋸的地方，火花從那裡噴出來。

## 行為

- 兩色交界有一顆白色光點持續閃爍，隨比例移動（0.6 秒過渡，跟現有填色一致）。
- 某隊的**顯示總數增加**時，從交界點朝對方那側噴火花：
  - 增加的來源包括自己按、別人的批次經由輪詢或送出回應進來，一律同一套規則。
  - 顆數 = min(5 + 增加量, 18)：自己按一下噴 6 顆，別人一次湧進一大批最多 18 顆。
  - 顏色在該隊色、黃（#ffd23f）、白之間輪替；往前上下 ±63° 散開、飛 14–48px、0.38–0.7 秒淡出。
- 第一次拿到伺服器總數時不噴：打開頁面時總數是從 0 跳到幾千，那不是有人在加油。
- 2 秒內超過 10 下、沒有算進去的點擊不噴（數字也沒動）。
- 同時存在的火花最多 60 顆，滿了這一批就少噴。
- 系統開了「減少動態效果」時不噴，光點也不閃；分頁在背景時不噴。
- 瀏覽器不支援動畫，或火花出錯時靜默略過，應援數與比分照常。

## 反目標

- 手機卡頓。
- 375px 寬出現水平捲動，包括比例 0% 或 100% 時火花飛出應援區邊緣。
- 影響比分輸入或應援數字。

## 做法比較

| 做法 | 取捨 | 結果 |
|---|---|---|
| A 交界火花 | 所有人都看得到彼此的應援；要把「增加量」從控制器傳到畫面 | **選用** |
| B 按鈕噴火花 | 只有按的人看得到，跟現有按鈕縮放回饋重疊 | 不用 |
| C 兩者都要 | 畫面最熱鬧，同時存在的火花數也加倍 | 不用 |

實作方式選 DOM 小元素加 Web Animations：每顆火花只動 transform 與 opacity，跑完就移除。
canvas 需要一個常駐的繪圖迴圈，這個量級沒有必要。

## 我做的決定（使用者可改）

- 顆數公式、上限 60、顏色輪替、飛行距離與時間都照試玩版。
- 應援區加 `overflow: hidden`，讓火花不會撐出水平捲動。火花飛出應援區邊界的部分會被切掉，這是可接受的代價。
