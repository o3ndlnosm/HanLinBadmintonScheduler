# 應援泡泡＋比賽結束才公布應援數（短設計）

2026-11-17。接續 `2026-11-17-cheer-sparks-design.md`（交界火花）。

## 為什麼

應援條純粹是炒氣氛。火花讓人看到「交界在拉鋸」；泡泡要讓人看到「是哪一邊在喊」。
使用者判斷比賽當下應援數字不重要：誰領先看條就知道，按下去有火花回饋；
數字改成比賽結束時才公布，當作全場收尾的時刻。

## 行為

### 比賽中（15 場還沒全部確認）

- 應援條上方那一行只顯示兩隊隊名（左 A、右 B），**不顯示數字**。
- 某隊顯示總數增加時（跟火花同一個觸發：自己按、別人的批次都算），在該隊那一側冒一個對話泡泡：
  - 一次增加只冒 1 個，不論增加多少；每側同時最多 3 個，滿了這次不冒。
  - 文字從固定口號隨機挑：
    - 通用：「加油！」「衝啊！」「好球！」「穩住！」「漂亮！」「拿下這分！」
    - 帶隊名：「{隊名}加油！」「{隊名}衝衝衝！」「{隊名}必勝！」
    - 不放嗆對方的話。
  - 泡泡底色是隊色、白字；A 隊從左側冒、B 隊從右側冒，水平位置在該側隨機；約 1.4 秒內彈出、上飄、淡出後移除。
  - 冒在隊名那一行上，可以短暫蓋住隊名；應援區不加高。
- 第一次拿到伺服器總數不冒（同火花）；系統開了「減少動態效果」、分頁在背景時不冒；出錯靜默略過，不影響應援數與比分。

### 15 場全部確認後（點數計分板出現「比賽結束」的同一時刻）

- 隊名那一行換成「應援總數」與兩隊數字，例如：`應援總數　貿聯 1,234 ｜ 987 翰林`，之後照常每 3 秒更新。
- 判斷沿用點數計分板的 `computeTeamPoints(...).allConfirmed`，不另寫一套「比賽結束」的判斷。

### 比賽被設成 finished 之後（賽後收尾 SQL 鎖定比分與應援）

- 現在：應援條整個不掛。
- 改成：仍顯示應援條與「應援總數」，但**沒有加油按鈕**（後端本來就擋應援；讀總數的 RPC 在 finished 後仍可用，已查 `tournament_cheer_totals`）。
  不這樣做的話，收尾之後才打開頁面的人看不到公布的數字。

## 反目標

- 手機卡頓。
- 375px 寬出現水平捲動。
- 影響比分輸入或應援數字。
- 比賽中在畫面上露出應援數（應援條的比例本來就看得到，這是接受的）。

## 做法比較

| 決定 | 做法 | 取捨 | 結果 |
|---|---|---|---|
| 泡泡文字 | 固定口號隨機挑 | 純前端、不動後端；內容可控 | **選用** |
| | 讓大家自己打字 | 最有參與感；要新資料表與 RPC、擋不雅字和洗版，公開頁當天沒人即時管理 | 不用 |
| 應援數 | 比賽中顯示（現狀） | 數字一直跳；泡泡要另外找位置（加高或蓋住數字） | 不用 |
| | 「確定勝出」時公布 | 之後還有比賽、大家還在按，數字要嘛繼續跳要嘛凍結 | 不用 |
| | 15 場全部確認時公布 | 頁面已有這個判斷；全場收尾最自然 | **選用** |
| | 完全不顯示 | 最簡單，但少了收尾的時刻 | 不用 |

實作方式：泡泡沿用火花的觸發（控制器的 `bursts`）與疊在應援條上的特效層，DOM 小元素＋Web Animations，跑完就移除。
公布狀態由 `tournament.js` 每次刷新時把 `allConfirmed` 與比賽是否 finished 交給應援條。`?v=` 與 `sw.js` CACHE_NAME 一起升到 18。

## 我做的決定（使用者可改）

- 口號清單、每側同時最多 3 個、1.4 秒。
- 公布之後，加油按鈕、火花、泡泡照常（比賽 finished 之前大家仍可以按）。
- 比賽設成 finished 後仍顯示應援總數（唯讀、沒有按鈕）。
- 公布那一行用「應援總數」字樣，數字格式同現在（千分位）。
